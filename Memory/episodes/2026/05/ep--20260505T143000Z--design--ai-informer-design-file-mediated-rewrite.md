## Reflection

The architectural correction landed cleanly because the human's R1/R2/R3/S1/S2 was sharply numbered and each item had concrete acceptance criteria. Three substantive shifts: (1) subagent contracts are now natural-language input/middle/output prose — strict-JSON LLM-return contracts are gone everywhere they had no business being (between main agent and inline subagent); JSON only persists where it is the on-disk shortlist.json shape, which is genuine structured data not an LLM return shape. (2) The screener gained file-read+file-write capability: it consumes a stripped per-line representation (produced by a shared helper script) so the full collected JSON never enters its context, and writes shortlist.json so the main agent doesn't carry the full filtered list either. The token-budget logic of file-mediated handoff is the load-bearing reason — context bloat was the implicit failure mode. (3) The per-run intermediate-artifacts directory `Runtime/runs/<window>/<YYYYMMDD-HHMM>/{collected.json, stripped.txt, shortlist.json, briefings/<record_id>.md, output.md}` is a single canonical home for every artifact a run produces, named identically across screener.md, all three skill outlines, and main design §3 / §6. Window-specific guidance was kept in design/skills/window-*.md only, NOT bled into design/subagents/*.md — a temptation worth resisting. One minor evaluator-noted divergence remains: §3's stripped-line description includes `joined source_categories` while screener.md's example format omits it (both are illustrative prose, not strict schema, both correctly exclude raw_items, both use only canonical fields). Reconciliation is one-line and queued for a tiny prelude before scaffolding.
