## Reflection

Three calls worth recording: (1) The OPTION X validate-then-install discipline paid off exactly as designed. The Codex sandbox network policy would have caused silent or absent broadcasts at the first daily cron fire — discovering that issue at 08:00 in cron logs would have been much harder to debug than discovering it in 9 minutes of foreground autonomous execution with full trajectory capture. The lesson generalizes: foreground autonomous validation BEFORE installing scheduled triggers is the right ordering. Worth promoting to durable knowledge as a small "scheduler-installation-precondition" heuristic. (2) The Codex sandbox network surprise is a real, recurrent class of issue worth its own knowledge note. Two-instance evidence: ai_sources adapters AND notifications CLI both failed identically inside the sandbox with `gaierror -3`, while host-side curl/getent succeeded against the same hostnames. Any future Codex-hosted CLI doing naive HTTP/urlopen to external services will trip on this. The mitigation playbook needs design (split synthesis from delivery so the Codex stage stops after generating output.md, then a host-side delivery wrapper handles the broadcast; or enable network in the run-once.sh wrapper if Codex SDK exposes that). (3) The agent's autonomous adaptation (web_search fallback when ai_sources failed) is interesting but unplanned. Sometimes desirable (graceful degradation), sometimes not (silently shifts source-of-truth from ai_sources canonical records to web_search snapshots). Should be designed in or designed out explicitly, not left emergent. The next planning heartbeat should make a deliberate call on this.
